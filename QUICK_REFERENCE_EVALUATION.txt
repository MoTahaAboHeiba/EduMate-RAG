 EVALUATION METRICS EXPLAINED


RETRIEVAL METRICS (How well we find relevant docs)

Precision@3: Out of top-3 retrieved docs, how many are relevant?
   Score: 0-1 (1=all relevant)
   Target: ≥70%
   
Recall@5: Of all relevant docs, how many are in top-5?
   Score: 0-1 (1=all found)
   Target: ≥60%
   
MRR: At what position is the first relevant doc?
   Score: 0-1 (1=first position)
   Target: ≥75%
   
NDCG@10: Is ranking quality good?
   Score: 0-1 (1=perfect ranking)
   Target: ≥70%


GENERATION METRICS (Quality of generated answers)

Faithfulness: Is answer grounded in sources?
   Score: 0-1 (1=completely grounded)
   Target: ≥95%
   
Relevance: Does answer address the question?
   Score: 0-1 (1=fully relevant)
   Target: ≥90%
   
Completeness: Is information sufficient?
   Score: 0-1 (1=fully complete)
   Target: ≥80%
   
Source Accuracy: Are cited sources correct?
   Score: 0-1 (1=all correct)
   Target: ≥95%


PERFORMANCE METRICS (System speed & resources)

Avg Latency: Average query response time in ms
   Target: ≤3000ms (3 seconds)
   
P95 Latency: 95th percentile query time
   Target: ≤5000ms (5 seconds)
   
Throughput: Queries per second
   Target: ≥0.5 q/s (1 query per 2 seconds)
   
Memory Usage: RAM consumed
   Target: ≤2048MB (2 GB)


 TYPICAL WORKFLOW


Day 1: Baseline Evaluation

   2. Run Phase 3: python evaluation/run_evaluation.py
   3. Run Phase 4: python evaluation/analyze_results.py
   4. Review report: evaluation/results/evaluation_report.html

Day 2-N: Optimization Loop
   1. Identify weak areas from report
   2. Make code changes
   3. Re-run Phase 3 & 4
   4. Compare improvements
   5. Repeat until targets met


 DEBUGGING TIPS


If Phase 3 fails:
 Check if server is running: curl http://localhost:8000/health
 Check for API errors in server terminal
 Verify dataset file exists: evaluation/datasets/rag_evaluation_dataset_v1.json
 Check evaluation/results/ for error logs

If metrics look bad:
 Check retrieval vs generation issues separately
 Review sample answers in evaluation/results/
 Look at categories with lowest scores
 Check if certain PDFs have low quality

If performance is slow:
 Check Groq API status
 Check network connection
 Review chunk size settings
 Check server logs for bottlenecks

 TIPS FOR SUCCESS


 Start with baseline: Don't change anything on first run
 Focus on gaps: Improve weakest areas first
 Test incrementally: Make one change at a time
 Track results: Save each run's metrics
 Document changes: Keep notes on what you tried
 Be patient: RAG systems improve gradually
 Use visualizations: Charts help identify patterns


 LEARNING FROM RESULTS


Low Precision?  Retrieved docs are not relevant
   Fix: Improve embedding model or retrieval parameters

Low Recall?  Missing relevant documents
   Fix: Adjust chunk size or retrieval top-k

Low Faithfulness?  Answers hallucinate
   Fix: Add stricter prompts or retrieval validation

Low Latency?  System is too slow
   Fix: Optimize chunk processing or API calls
